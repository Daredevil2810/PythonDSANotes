Exception handling

Keep your program alive when things go wrong.

1What is it?

An exception is an error that happens while the program is running. try holds risky code, except says what to do if it fails, finally always runs, and raise lets you create an exception yourself.

2Why do we need it?

Users type letters instead of numbers, files go missing, networks drop. Good programs handle these gracefully instead of crashing.

3In plain words

Everyday example

You're cooking and the gas runs out. try: cook the meal. except: if the gas fails, switch to the induction stove. finally: either way, wash the pan afterwards.

Precise definition

Python checks except clauses in order and runs the first one that matches. except Exception as e catches almost everything and gives you the error object. A syntax error is detected before the program runs; an exception happens at runtime.

4Code, step by step

try / except / finally

lesson_1.py
def safe_divide(a, b):
    try:
        print(a / b)
    except ZeroDivisionError:
        print("Cannot divide by zero!")
    except TypeError:
        print("Invalid input, not a number!")
    finally:
        print("Execution complete.")

safe_divide(10, 2)
safe_divide(10, 0)
safe_divide(10, "x")

except ZeroDivisionError:Runs only if the error is a division by zero.

Catching several errors, and raising your own

lesson_2.py
try:
    nums = [1, 2, 3]
    print(nums[5])
except IndexError as e:
    print("Error:", e)

try:
    int("abc")
except (ValueError, ZeroDivisionError):
    print("Handled multiple exceptions")

age = 15
try:
    if age < 18:
        raise ValueError("You must be at least 18 years old")
except ValueError as e:
    print(e)

5Common mistakes

  • A bare except: that hides every error, including ones you needed to see.
  • Putting too much code inside try. Wrap only the risky line(s).
  • Catching a general Exception before a specific one; the specific block never runs.

6When should I use it?

Wrap operations you can't fully control (user input, files, network). Raise your own exceptions to enforce business rules.

7Interview questions

What is the purpose of finally?

Code in finally always runs, and is used for cleanup.

Difference between syntax error and exception?

A syntax error is found before running. An exception happens at runtime.

Can we use multiple except blocks?

Yes, or one block with a tuple: except (ValueError, ZeroDivisionError):.

Why raise exceptions manually?

To enforce business logic or validation rules.

8Try it yourself

Write to_int(text) that returns int(text), or prints Not a number and returns None if conversion fails. Test it with "42" and "hi".

Show hint
Hint: int("hi") raises a ValueError.
Show solution
solution.py
def to_int(text):
    try:
        return int(text)
    except ValueError:
        print("Not a number")
        return None

print(to_int("42"))
print(to_int("hi"))
OUTPUT
42
