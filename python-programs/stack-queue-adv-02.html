Implement Queue Using Stack in Python

Use one stack for incoming elements and another for outgoing elements so two LIFO structures together behave like a FIFO queue.

1Python program

program_02.py
# Implement Queue Using Stack :

class QueueUsingStack:
    def __init__(self):
        self.stack1 = []
        self.stack2 = []

    def is_empty(self):
        return not self.stack1 and not self.stack2

    def enqueue(self, value):
        self.stack1.append(value)

    def dequeue(self):
        if not self.stack2:
            while self.stack1:
                self.stack2.append(self.stack1.pop())
        if not self.stack2:
            print("Queue Underflow")
            return None
        return self.stack2.pop()

    def peek(self):
        if not self.stack2:
            while self.stack1:
                self.stack2.append(self.stack1.pop())
        if not self.stack2:
            print("Queue is empty")
            return None
        return self.stack2[-1]

    def display(self):
        temp = self.stack2[::-1] + self.stack1
        print(temp)

queue = QueueUsingStack()
queue.enqueue(10)
queue.enqueue(20)
queue.enqueue(30)

print("Queue:")
queue.display()
print("Front element:", queue.peek())
print("Dequeued:", queue.dequeue())
print("Queue after dequeue:")
queue.display()


# Output :

# Queue:
# [10, 20, 30]
# Front element: 10
# Dequeued: 10
# Queue after dequeue:
# [20, 30]

2Why it matters

This is a classic interview problem that demonstrates how reversing order twice can reproduce queue behavior.

Simple example

Enqueue 10, 20, 30 into stack1. When dequeue is needed, move them to stack2: stack2 becomes [30, 20, 10], so 10 is now on top and leaves first.

3How it works

  1. Push every newly enqueued item onto stack1.
  2. For dequeue or peek, if stack2 is empty, move every item from stack1 to stack2.
  3. The transfer reverses the order.
  4. Read or remove the top of stack2.
  5. Keep stack2 until it becomes empty before transferring again.

6Time and space complexity

Time: Amortized O(1) enqueue/dequeue; O(n) for a transfer

Space: O(n)

7Common mistakes

  • Transferring every time instead of only when stack2 is empty.
  • Confusing the top of stack2 with the newest item.
  • Assuming every individual dequeue is always O(1).

8When to use it (and when not to)

Use it when: Use it to understand amortized analysis and how two LIFO structures can implement FIFO behavior.

Avoid it when: In ordinary Python code, prefer collections.deque unless the interview specifically asks for this implementation.

9Interview questions to expect

  • Why is the amortized dequeue complexity O(1)?
  • Why must transfer happen only when stack2 is empty?
  • What happens if an enqueue occurs while stack2 still contains elements?
