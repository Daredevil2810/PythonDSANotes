Stack Using Single Queue (Efficient Pop) in Python

Simulate LIFO stack behavior with a single FIFO queue by rotating the existing elements after every push.

1Python program

program_01.py
# Stack Using Single Queue (Efficient Pop) :

from collections import deque

class StackUsingQueue:
    def __init__(self):
        self.queue = deque()

    def is_empty(self):
        return len(self.queue) == 0

    def push(self, value):
        size = len(self.queue)
        self.queue.append(value)
        for _ in range(size):
            self.queue.append(self.queue.popleft())

    def pop(self):
        if self.is_empty():
            print("Stack Underflow")
            return None
        return self.queue.popleft()

    def peek(self):
        if self.is_empty():
            print("Stack is empty")
            return None
        return self.queue[0]

    def display(self):
        print(list(self.queue))

stack = StackUsingQueue()
stack.push(10)
stack.push(20)
stack.push(30)

print("Stack:")
stack.display()
print("Top element:", stack.peek())
print("Popped:", stack.pop())
print("Stack after pop:")
stack.display()


# Output :

# [30, 20, 10]
# Top element: 30
# Popped: 30
# Stack after pop:
# [20, 10]

2Why it matters

It shows how one data structure can be used to reproduce the behavior of another and strengthens your understanding of operation trade-offs.

Simple example

Push 10, then 20, then 30. After each push, rotate the older elements behind the new value, so the queue becomes [30, 20, 10]. Removing from the front therefore behaves like stack pop.

3How it works

  1. Keep one queue containing the stack elements.
  2. Append the new value to the back of the queue.
  3. Remember the queue size before the append.
  4. Rotate exactly that many old elements from front to back.
  5. The newest value is now at the front, so pop and peek are O(1).

6Time and space complexity

Time: O(n) push, O(1) pop/peek

Space: O(n)

7Common mistakes

  • Rotating the newly added value too.
  • Rotating the wrong number of elements.
  • Assuming both push and pop can be O(1) with this single-queue strategy.

8When to use it (and when not to)

Use it when: Use it as an interview exercise for understanding data-structure simulation and operation trade-offs.

Avoid it when: Avoid this implementation when a normal stack is available and performance simplicity matters.

9Interview questions to expect

  • Why is push O(n) here?
  • How would the complexity change if pop were made expensive instead?
  • Can a stack be implemented with a queue while keeping both push and pop O(1)?
