Delete Node from End in Python

Find the second-to-last node and set its next reference to None.

1Python program

program_06.py
# Delete Node from End :

# Update secondToLast.next = null, If the list has only one node, set head = null.

class Node:
    def __init__(self, data):
        self.data = data
        self.next = None

def delete_from_end(head):
    if head is None:        # Empty list
        return None
    if head.next is None:   # Single node
        return None

    current = head
    while current.next.next:  # Traverse to second-to-last
        current = current.next
    current.next = None       # Delete last node
    return head

def display(head):
    current = head
    while current:
        print(current.data, end=" -> ")
        current = current.next
    print("None")

head = Node(10)
head.next = Node(20)
head.next.next = Node(30)

print("Original Linked List:")
display(head)

head = delete_from_end(head)
print("After Deleting from End:")
display(head)


# Output :

# Original Linked List:
# 10 -> 20 -> 30 -> None
# After Deleting from End:
# 10 -> 20 -> None

2Why it matters

A singly linked list has no backward pointer, so the predecessor must normally be found first.

Simple example

10 → 20 → 30 becomes 10 → 20 by changing 20.next to None.

3How it works

  1. Handle an empty list.
  2. Handle a single-node list.
  3. Traverse until current.next.next is None.
  4. Set current.next to None.

4Line-by-line meaning

6Time and space complexity

Time: O(n)

Space: O(1)

7Common mistakes

  • Handle the one-node case first.
  • Do not walk to None because the predecessor is needed.
  • Remember that a singly linked list cannot move backward.

8When to use it (and when not to)

Use it when: Use it when deleting the last node without a tail/predecessor reference.

Avoid it when: Avoid repeated O(n) end deletions when a doubly linked list or another structure is more suitable.
