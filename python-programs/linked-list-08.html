Search Node in Linked List in Python

Traverse from head and compare each node with the target until a match is found or the list ends.

1Python program

program_08.py
# Search Node in Linked List :

# Search for a node with a given value in a singly linked list, Return its position (1-based index) if found, If not found, return -1 or display "Not found".

class Node:
    def __init__(self, data):
        self.data = data
        self.next = None

def search_node(head, key):
    current = head
    position = 1
    while current:
        if current.data == key:
            return position
        current = current.next
        position += 1
    return -1  # Not found

def display(head):
    current = head
    while current:
        print(current.data, end=" -> ")
        current = current.next
    print("None")

head = Node(10)
head.next = Node(20)
head.next.next = Node(30)
head.next.next.next = Node(40)

print("Linked List:")
display(head)

key = 30
pos = search_node(head, key)
if pos != -1:
    print(f"Element {key} found at position {pos}")
else:
    print(f"Element {key} not found")


# Output :

# Linked List:
# 10 -> 20 -> 30 -> 40 -> None
# Element 30 found at position 3

2Why it matters

Normal singly linked lists do not support direct indexed lookup, so search is sequential.

Simple example

Searching for 30 in 10 → 20 → 30 → 40 checks three nodes and returns position 3.

3How it works

  1. Start at head.
  2. Compare the current value with the target.
  3. Return its position on a match.
  4. Otherwise advance to the next node.
  5. Return -1 if the list ends.

6Time and space complexity

Time: O(n) worst case

Space: O(1)

7Common mistakes

  • Forgetting to advance current.
  • Using an inconsistent not-found result.
  • Not handling an empty list.

8When to use it (and when not to)

Use it when: Use it for unsorted linked lists or when direct node references are unavailable.

Avoid it when: Do not expect efficient binary-search behavior from a normal singly linked list.

9Interview questions to expect

  • Why is search O(n)?
  • What is the best case?
  • How would you return the node instead of its position?
