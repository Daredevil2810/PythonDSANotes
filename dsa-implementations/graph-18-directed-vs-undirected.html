Model Directed vs Undirected Graphs in Python

Directed edges have a direction; undirected edges represent a two-way relationship.

1Why this matters

Many graph algorithms depend on whether an edge can be traversed in one direction or both.

Approach

For an undirected edge u-v, store both u→v and v→u. For a directed edge u→v, store only u→v.

2Python implementation

Python
directed = {
    'A': ['B'],
    'B': []
}

undirected = {
    'A': ['B'],
    'B': ['A']
}

print(directed['B'])
print(undirected['B'])

3Expected output

OUTPUT / RESULT
[]
['A']

4Line by line

CodeMeaning
directed['A'] = ['B']A can reach B, but the reverse is not implied.
undirected['B'] = ['A']The reverse relationship is stored explicitly.

5Dry run

In the directed graph, B has no outgoing edge. In the undirected graph, B can return to A because the connection works both ways.

6Complexity

O(V + E) storage for adjacency lists.

7Common mistakes

  • Automatically adding reverse edges to a directed graph.
  • Forgetting both directions in an undirected adjacency list.

8When to use it

Use directed graphs for dependencies, one-way links and prerequisite relationships; use undirected graphs for mutual connections such as two-way roads.

9Interview questions

How do you represent an undirected edge in an adjacency list?

Add each endpoint to the other endpoint's neighbor list.
