DSA interview questions

Answer from memory first, then reveal the explanation. Focus on ideas, complexity, trade-offs and edge cases.

What does Big O notation describe?

Big O describes how an algorithm's time or space requirement grows as the input size grows. It focuses on the growth rate rather than an exact machine-dependent runtime.

Tip: Always state what n represents. For example, scanning an array is O(n) where n is the number of elements.

Why is accessing an array element by index usually O(1)?

An array stores elements in contiguous positions, so the address of an indexed element can be calculated directly from the starting address and the index. The lookup does not require scanning earlier elements.

Tip: Contrast this with a linked list, where reaching the kth node requires traversal.

What is the typical cost of inserting into the middle of an array?

Usually O(n), because elements after the insertion point have to be shifted to make room. Inserting at the end can be O(1) amortized for a dynamic array when capacity is available.

Tip: Mention that the exact cost depends on where the insertion happens and the array implementation.

Why does Python string immutability matter in algorithm problems?

A string cannot be changed in place. Operations that appear to modify a string generally create a new string, so repeated concatenation can add extra time and memory. A list of characters or a builder-style approach can be preferable for heavy construction.

Tip: Explain the algorithmic consequence instead of only saying 'strings are immutable'.

How would you solve Two Sum efficiently?

Scan the array once while storing previously seen values in a hash map. For each value x, check whether target - x is already present. This gives O(n) expected time and O(n) extra space.

Tip: Be ready to explain why the complement lookup is the key idea.

When is a frequency map useful?

Use it when the problem asks how often values occur, whether two collections have matching counts, or whether a value has already appeared. A dictionary usually gives expected O(1) lookup and update time.

Tip: Common signals are words such as frequency, count, duplicate, anagram, or occurrence.

What condition is required for ordinary binary search?

The search space must have a predictable ordering that lets you discard half of it after each comparison. The classic array version requires the values to be sorted according to the searched ordering.

Tip: Do not memorize binary search as 'works on arrays'; the important property is a monotonic search space.

Why is binary search O(log n)?

Each comparison cuts the remaining search space roughly in half. After k halvings, about n / 2^k elements remain. Reaching one candidate takes about log2(n) halvings.

Tip: A simple halving explanation is usually enough in an interview.

What does it mean for a sorting algorithm to be stable?

A stable sort preserves the relative order of elements that compare equal. This matters when records have multiple fields and you want an earlier ordering to remain intact for equal keys.

Tip: Give a small example such as sorting people by age while preserving their previous name order.

Why is merge sort O(n log n)?

The array is divided into about log n levels of recursion, and each level processes all n elements while merging. Therefore the total work is O(n log n), with O(n) auxiliary space for the usual array implementation.

Tip: Separate the depth of the recursion from the work done at each level.

When would you prefer a linked list over an array?

A linked list can be useful when frequent insertions or deletions occur at known nodes and random indexing is not important. Arrays are usually better when fast indexed access and cache-friendly traversal matter.

Tip: Avoid saying linked lists are always faster for insertion; locating the insertion point can still cost O(n).

How do you reverse a singly linked list iteratively?

Keep three references: previous, current, and next. Save current.next, point current.next to previous, move previous to current, and move current to the saved next node. Continue until current is None, then return previous.

Tip: The critical safety step is saving next before changing current.next.

How does Floyd's cycle detection algorithm work?

Use a slow pointer that moves one step and a fast pointer that moves two. If there is a cycle, they eventually meet inside it. If fast reaches the end, there is no cycle. Time is O(n) and extra space is O(1).

Tip: If asked why they must meet, explain that the fast pointer gains one node per step relative to the slow pointer inside the cycle.

What is the difference between a stack and a queue?

A stack is LIFO: the last item added is the first removed. A queue is FIFO: the first item added is the first removed. Stacks are common for nested work and undo-like behavior; queues are common for scheduling and breadth-first processing.

Tip: Give one real use case for each rather than only defining the acronyms.

Why is a stack a natural solution for balanced parentheses?

Opening brackets create unresolved obligations. A stack stores the most recent opening bracket, so the next closing bracket can be checked against the correct opener. Any mismatch or leftover opener means the sequence is invalid.

Tip: This is an example of matching nested structure with LIFO behavior.

Why does breadth-first search use a queue?

BFS processes nodes level by level. A queue preserves the order in which nodes are discovered, so nodes from the current frontier are processed before nodes discovered at later levels.

Tip: If the graph is unweighted, BFS can also find a shortest path in number of edges.

What are the two essential parts of a recursive function?

A base case that stops recursion and a recursive step that moves the problem toward that base case. Without a reachable base case, recursion does not terminate.

Tip: When reviewing recursion, explicitly identify the smaller subproblem and the stopping condition.

What extra space does recursion use?

Recursive calls use the call stack. If the maximum recursion depth is d, the call-stack space is generally O(d), even when the algorithm does not allocate another explicit data structure.

Tip: This is why a recursive algorithm can be O(n) space even when its local variables are constant-sized.

When should you consider dynamic programming?

Look for overlapping subproblems and optimal substructure: the same smaller problems are solved repeatedly, and an optimal solution can be built from optimal solutions to smaller states. DP stores those results instead of recomputing them.

Tip: A useful interview phrase is 'define the state before writing the recurrence'.

What is the difference between memoization and tabulation?

Memoization is top-down: start from the target and cache recursive results as they are needed. Tabulation is bottom-up: fill a table from smaller states toward the target, usually with loops.

Tip: Mention that both techniques trade extra memory for avoiding repeated computation.

How do you design a DP state?

Choose the smallest information needed to describe a subproblem so that the answer can be derived from previously solved states. Then define the transition, base cases, and the order in which states are evaluated.

Tip: If the state contains unnecessary information, the DP can become much larger than necessary.

How is a greedy algorithm different from dynamic programming?

A greedy algorithm commits to a locally best choice and relies on a proof that those choices lead to a global optimum. Dynamic programming considers combinations of subproblems and stores their best results. Greedy is often simpler, but it only works when the required greedy property holds.

Tip: Do not claim that greedy works because it 'looks optimal'; be ready to justify the choice.

What does the bitwise AND operator do?

It compares corresponding bits and produces 1 only when both bits are 1. It is useful for masking, checking selected bits, and clearing or retaining portions of a binary representation.

Tip: A binary example is often clearer than a decimal-only explanation.

Why can XOR find the unique element when every other value appears twice?

XOR is self-canceling: x XOR x is 0, and x XOR 0 is x. XORing all values therefore cancels every pair and leaves the unpaired value. This uses O(n) time and O(1) extra space.

Tip: This is a classic example where an algebraic property removes the need for a hash set.

What problem shape suggests a sliding-window technique?

Problems involving contiguous subarrays or substrings with a condition that changes as the left or right boundary moves are strong candidates. Instead of recomputing each range from scratch, maintain the current window's state while expanding and shrinking it.

Tip: Ask whether adding the next element and removing the left element can update the state efficiently.

When is the two-pointer technique useful?

It is useful when two positions can move through a sequence while maintaining a relationship between them. Common examples include sorted-array pair problems, merging sequences, and shrinking a range from both ends.

Tip: The pointers should have a reason to move; explain the invariant that makes a move safe.

What does a prefix sum array help you do?

It converts repeated range-sum queries into constant-time lookups after O(n) preprocessing. With prefix[i] representing the sum before or through a position, a range sum can be obtained by subtracting two prefix values.

Tip: Be precise about whether your prefix definition includes the current element.

What is an algorithmic invariant?

An invariant is a condition that remains true throughout an algorithm or loop. It helps explain why each step is safe and why the final state gives the correct result.

Tip: For two pointers or binary search, stating the invariant often makes the solution much easier to defend.

What is a time-space trade-off?

It means using additional memory to reduce computation time, or sometimes accepting more computation to save memory. Hash maps for fast lookup and memoization for cached subproblems are common examples.

Tip: Interviewers often care about whether you can consciously choose the trade-off rather than only quote a complexity.

Which edge cases should you check before coding an algorithm?

At minimum consider empty input, one element, duplicate values, already sorted or reverse-sorted input, boundary indices, negative or zero values when relevant, and unusually large input. The exact cases depend on the problem constraints.

Tip: Mention edge cases while discussing the approach, not only after writing code.
