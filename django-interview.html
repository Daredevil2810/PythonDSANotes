Django & Web interview

Move from Python and DSA fundamentals into framework, API and web-development interview questions.

What is Django's MVT architecture?

MVT stands for Model, View and Template. Models describe data and database behavior, views contain request-handling logic, and templates present data to the user. Django's URL configuration connects incoming paths to views.

Tip: Explain the request flow rather than only expanding the acronym.

What happens when a request reaches a Django application?

The request enters Django's middleware stack, URL resolution finds a matching pattern, the selected view runs, and the view can interact with models or other services before returning an HttpResponse. Response middleware then runs on the way back out.

Tip: Middleware sits around the view, so it can act before and after the view executes.

What is the difference between a Django project and an app?

A project is the overall configuration and collection of components for a site. An app is a reusable unit focused on a particular domain or feature, such as users, billing or products.

Tip: A single project can contain multiple apps.

What is settings.py used for?

It contains project configuration such as installed apps, middleware, database settings, templates, static files, security options and environment-specific configuration.

Tip: In production, keep secrets out of source code and load sensitive values from the environment or a secret manager.

What is URLconf in Django?

URLconf maps URL patterns to views. Django checks patterns in order and calls the view associated with the first match.

Tip: Mention path converters or include() when discussing larger projects.

Why use include() in Django URLs?

include() lets a project delegate part of the URL tree to an app's own URLconf. This keeps routing modular and avoids putting every route in one file.

Tip: Think of it as composing URL trees from smaller app-level route sets.

What is a Django model?

A model is a Python class that represents structured application data and maps to database storage through Django's ORM. Fields define data types and relationships define how records connect.

Tip: A model is more than a table definition because it can also contain behavior and validation-related logic.

What are migrations?

Migrations are versioned instructions that describe changes to the database schema based on model changes. makemigrations creates migration files and migrate applies them to the database.

Tip: Keep migrations under version control so environments can reproduce schema changes.

What is a QuerySet?

A QuerySet represents a collection of database queries or results managed by Django's ORM. QuerySets are lazy: many operations build a query without immediately hitting the database, and evaluation occurs when results are needed.

Tip: Lazy evaluation is a common interview follow-up.

What is the difference between filter() and get()?

filter() returns a QuerySet and can represent zero, one or many matching records. get() expects exactly one object and raises an exception if zero or multiple objects match.

Tip: Use get_object_or_404 when a missing object should become a 404 response.

What does select_related() do?

select_related() follows foreign-key or one-to-one relationships using SQL joins so related objects can be retrieved efficiently with the main query. It is useful for reducing repeated database queries when traversing single-valued relationships.

Tip: Contrast it with prefetch_related for many-valued or reverse relationships.

What does prefetch_related() do?

prefetch_related() fetches related collections using additional queries and combines them in Python. It is useful for many-to-many and reverse relationships where a SQL join could multiply rows.

Tip: The simple interview contrast is select_related uses joins; prefetch_related uses separate queries and combines results.

What is the N+1 query problem?

It occurs when code runs one query to fetch N objects and then performs another query for each object's related data, producing 1 + N database queries. Relationship prefetching or selecting can often reduce this to a small fixed number of queries.

Tip: Django Debug Toolbar is useful during development for spotting unexpected query counts.

Why use transaction.atomic()?

transaction.atomic() groups database operations into a transaction so they either all commit successfully or are rolled back when an error causes the transaction to fail. This protects consistency across related writes.

Tip: Use transactions when several writes must succeed or fail together.

What is the purpose of a Django Form?

A Form defines and validates user input. It can convert raw submitted values into cleaned Python values and report validation errors in a structured way.

Tip: ModelForm can derive many fields and validation rules from a model.

What is a ModelForm?

A ModelForm is a form class tied to a Django model. It can generate form fields from model fields and save validated data to a model instance when used appropriately.

Tip: You still need to choose fields explicitly rather than exposing every model field by default.

What is CSRF protection in Django?

CSRF protection helps prevent a malicious site from causing a user's browser to submit an unwanted state-changing request to your site. Django's CSRF middleware and template token mechanism provide protection for relevant form submissions.

Tip: Do not confuse CSRF with authentication; CSRF abuses an already authenticated browser session.

How does Django help reduce XSS risk?

Django templates escape variable output by default, which helps prevent injected HTML or script from being interpreted as markup. Developers can still create vulnerabilities by explicitly marking unsafe content as safe or bypassing escaping incorrectly.

Tip: Security features reduce risk but do not replace careful handling of untrusted input.

What is the difference between authentication and authorization?

Authentication answers who the user is. Authorization answers what that authenticated user is allowed to do.

Tip: Login is authentication; permission checks are authorization.

How does Django's session authentication work at a high level?

After successful authentication, Django associates the user with a session and sends a session identifier to the client. Later requests use that session so Django can identify the logged-in user.

Tip: Keep credentials and session identifiers separate conceptually.

How do Django permissions and groups help?

Permissions represent specific allowed actions, while groups provide a convenient way to assign sets of permissions to multiple users. Views can then check whether the current user has the required permission.

Tip: This is useful for role-based access patterns without hard-coding every user check.

What is the difference between static files and media files?

Static files are application assets such as CSS, JavaScript and images shipped with the application. Media files are user-uploaded content. They have different storage, deployment and security considerations.

Tip: Do not treat user uploads as trusted application assets.

Why use template inheritance?

A base template can define shared layout such as navigation and scripts, while child templates fill named blocks with page-specific content. This reduces duplication and keeps site-wide changes centralized.

Tip: block and extends are the key concepts to mention.

What is template context?

Context is the dictionary-like data passed from a view to a template so the template can render dynamic information. Good view logic prepares the data; templates should mainly present it.

Tip: Avoid putting heavy business logic into templates.

What is the difference between function-based and class-based views?

Function-based views use ordinary Python functions and can be very explicit. Class-based views package reusable behavior through inheritance and mixins and can reduce repeated CRUD-style view code, but they may be less obvious to beginners.

Tip: Choose based on clarity and reuse, not because one style is universally better.

What is Django REST Framework?

Django REST Framework is a toolkit for building APIs with Django. It provides serializers, API views, authentication and permission tools, routers and other components for representing application data over HTTP.

Tip: Separate DRF from Django itself: DRF is an additional framework built around Django.

What does a DRF serializer do?

A serializer converts complex Python or model data into representations such as JSON and can also validate incoming data before it is used to create or update objects.

Tip: Think of serialization as output representation plus input validation/deserialization.

What is an APIView in DRF?

APIView is a class-based view that gives explicit control over HTTP methods such as GET, POST, PUT, PATCH and DELETE. It is useful when you need behavior that does not fit a standard generic view neatly.

Tip: Generic API views trade some explicit control for reusable common behavior.

How is authentication different from permission checking in DRF?

Authentication identifies the requester and attaches authentication information to the request. Permission classes then decide whether that requester is allowed to perform the requested operation.

Tip: Authentication can succeed while authorization still fails.

What changes when deploying Django to production?

Use production settings, disable DEBUG, configure allowed hosts and trusted origins as needed, protect secrets, use a production WSGI or ASGI server, configure static/media storage, HTTPS, database settings, logging and security headers appropriately.

Tip: Deployment is not just 'run manage.py runserver'; that server is for development.
