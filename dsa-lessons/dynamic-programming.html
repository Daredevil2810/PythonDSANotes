Dynamic Programming in Python

Reuse overlapping subproblem answers instead of recomputing them.

1What is it?

Dynamic programming stores results of repeated subproblems and builds an optimal answer from smaller states.

2Why do we need it?

It turns many exponential recursive solutions into polynomial-time algorithms.

3How it works

Everyday idea

If you keep solving the same small question, write its answer down and reuse it.

Technical view

DP requires a state definition, transition, base cases, and an evaluation order or memoization strategy. It commonly exploits overlapping subproblems and optimal substructure.

  1. Define what a state means.
  2. Write the transition from smaller states.
  3. Set base cases.
  4. Choose memoization or bottom-up tabulation.
  5. Estimate states × transition cost.

4Python code, step by step

example.py
def fib(n):
    if n <= 1:
        return n
    dp = [0, 1]
    for i in range(2, n + 1):
        dp.append(dp[-1] + dp[-2])
    return dp[n]

print(fib(10))
OUTPUT / RESULT
55
CodeWhat it means
dp = [0, 1]Stores the first two states.
dp.append(dp[-1] + dp[-2])Builds the next state from previous states.

5Common mistakes

  • Defining a state that does not contain enough information.
  • Using DP when subproblems do not overlap.
  • Mixing indexing conventions.

6When should I use it?

Use DP when recursive choices revisit the same states and the answer can be expressed from smaller states.

7Interview questions

Memoization vs tabulation?

Memoization is top-down caching of recursive states; tabulation is bottom-up computation of states in order.
