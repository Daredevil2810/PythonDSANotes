Problem-solving patterns

Learn to recognise the shape of a problem before you start writing code.

Two Pointers

When to use: Sorted data, pairs, opposite ends, or two moving positions.

Use two indices and move them according to an invariant instead of checking every pair.

Sliding Window

When to use: Contiguous subarray/substring plus a condition that changes as the range moves.

Maintain one window and update its state incrementally instead of recomputing every range.

Prefix Sum

When to use: Many range-sum queries or a running cumulative quantity.

Precompute cumulative totals so a range can be answered by subtracting two prefixes.

Binary Search on a Monotonic Space

When to use: The answer space or predicate changes from false to true (or true to false) once.

Instead of searching values only, search an ordered answer space and repeatedly discard half of it.

Recursion / Divide the Problem

When to use: A problem naturally becomes the same problem on a smaller input.

Define a base case and reduce the problem until that base case is reached.

Backtracking

When to use: Generate combinations, permutations, paths, or choices while undoing decisions.

Choose, explore, then undo the choice so the same state can be reused for another branch.

Hash Map / Frequency Counting

When to use: Fast membership, frequency, duplicate detection, complements, or grouping.

Trade extra memory for near-constant expected lookup and update time.

Monotonic Stack

When to use: Next greater/smaller element, nearest boundary, or a value that remains useful until a stronger value arrives.

Keep candidates in monotonic order and remove entries that can no longer be the answer.

BFS / DFS Traversal

When to use: Graph/tree traversal, reachability, components, shortest unweighted paths, or exhaustive exploration.

Visit each reachable state once while choosing either level-order exploration (BFS) or depth-first exploration (DFS).
